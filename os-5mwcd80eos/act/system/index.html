1. System

all act is a show playback and monitoring system for iPad and Mac. Each device is a node on one AES67 network, sharing one PTP media clock. There is no central box.

2. Signal flow

  • Playback. A song is one file of interleaved float32 at 48 kHz, up to 16 channels (Core/stream/Player.hpp). The send thread asks the player for 48 frames per 1 ms packet at the next RTP timestamp, so there is no device clock on the iPad side. Gain 1 is bit-exact L24. Transport and level changes fade over 5 ms, and levels use a 10 ms one-pole (docs/aes67-stream.md). Continue makes the next song gapless.
  • Mixer. FOH levels, mute and solo per stem, saved per song. The FX return goes into the main mix only with Settings › FX Pads in Main Mix (actFxMain).
  • Vocals. There are two inputs. Each is a channel of any AES67 stream, an Rx channel (0.8.1), or the iPad's audio interface, which takes over while the stream is missing. The AUv3 chain runs on the vocal stream's 1 ms send thread, up to 8 effects per vocal. The default chain is pitch → level → ess → smooth → tone (App/Vocals.swift, App/VocalEngine.mm).
  • IEMs. IEM 1 and IEM 2 are stereo send mixes. They take the stems pre-fader, the vocals after their effects, the FX pair, the Mac's talkback, and 8 network sources (any node's channel through the router), each with a master (Core/stream/IemMixer.hpp). Sources are aligned to the sample by media time. Each IEM goes out as its own pair of act's vocal stream.
  • Talkback. Two one-channel streams, one each way, run all the time on the program's clock and stay hidden from program lists. Holding Talk opens the mic with a 5 ms fade. The Mac's side ducks the program 20 dB (optional), and the iPad's side ducks other apps' audio (optional).
  • Listen on iPad. One IEM also plays on the iPad's own output. The vocal thread writes it to a ring and never waits. The device engine reads it through a 4-point Hermite resampler holding 5 ms beyond one IO buffer, with drift trim of at most 0.1 %. A route change rebuilds only this engine (docs/STATUS.md 0.6).
  • Mac output. 16 outputs or more play the 16 channels 1:1. With fewer, even channels are summed to left and odd to right (Receiver.hpp, foldStereo).

SAP/SDP

  • SAP on 239.255.255.255:9875, every 5 s. The program is announced as "<name> 1-8" and "<name> 9-16".
  • SDP lines: ts-refclk:ptp=IEEE1588-2008:<grandmaster>:0, mediaclk:direct=0.
  • act's own attributes, which other gear ignores: a=x-act-part:<group> <n>/2 (one program across two streams), a=x-act-talkback, plus the vocal-stream and node-output attributes (Sap.hpp).
  • SAP/SDP is the source of truth for streams. The control channel adds channel labels and nodes.

Control channel and discovery

  • Bonjour _actnode._tcp, one service per node, named <group>.<node UUID> (group act by default). One TCP connection per pair; the node with the lower ID dials (Shared/NodeLink.swift).
  • Framing: a 4-byte big-endian length, then JSON (NodeMessage), at most 1 MiB. Kinds are hello, health (1/s), subscribe, unsubscribe and patch (0.8.1: set a remote node's Rx).
  • A node not heard for 5 s is offline. It is dialled again every second while it is still announced.
  • -actNodePort / -actNodePeers dial fixed ports with no Bonjour (used by the tests).

  • Subscriptions sit on the receiving side: Rx n is set to (node UUID, Tx channel ID). They are saved under actRx as JSON, keyed by Rx index, so they outlive stream addresses. A route whose source is absent waits in silence and becomes live again when the node returns (Shared/Routes.swift).
  • Router (Core/stream/Router.hpp): 8 subscribed streams at once, 64 destinations, one receiver per stream on the node's clock. Network destinations are read in media time, bit-exact, with a 4 ms delay (192 frames, minimum 1 ms). Device outputs are resampled.
  • The I/O patch (Shared/IOPatch.swift, key actIO) gives the numbers their meaning. Routing only shows numbers.

4. Audio engine

Render thread rules

  • The send thread is real-time: Mach time constraint with a 1 ms period, 0.3 ms computation and 0.9 ms constraint (Sender.cpp:245). If refused, it falls back to SCHED_FIFO at max−5.
  • The receive thread is real-time: period 1 ms, computation 0.2 ms, constraint 1.0 ms (Receiver.cpp:244). Since 0.4 its worst pickup is 0.62 ms (was 1.45 ms).
  • The PTP thread runs at high priority (PtpClock.cpp:191).
  • Vocal processing runs on the vocal stream's send thread: no Swift, no locks. A unit that fails is passed over and never reaches the network (STATUS 0.5).
  • Router pull and render never lock or allocate. Patching happens on the main thread (Router.hpp).
  • Meters accumulate lock-free on the audio thread with one taker (the display), and ballistics run in the core (act_stream.h).
  • The capture for verification is written by another thread through a queue.
  • pitch2 has an RTGuard proof: 0 allocations, 0 frees, 0 lock or wait calls in 10 s with parameter changes (Pitch2/README.md). The other units: untested with RTGuard.

Jitter buffer

ModeDepthRule
Wired2 ms (96 frames)
Wi-Fi20 ms (960)
Wi-Fi Safe50 ms (2400)
Auto2-100 ms99.99th percentile of transit (0.25 ms bins, 30 s windows) + 1 ms. It rises at once and falls only after 60 s below. It starts at Wired on a wired network and at Wi-Fi Safe on Wi-Fi (Receiver.cpp)

The timeline buffer is indexed by RTP timestamp, so loss and reordering show as missing frames, never shifts. On the Mac, play-out runs on the device clock through a 128-tap windowed-sinc resampler (4096 phases, cutoff 0.95, Kaiser 12). The step is the PTP rate fed forward, times a PI trim on the margin (0.1 rad/s, ±400 ppm).

Packet loss concealment

A gap of up to one packet (48 frames) repeats the last packet's frames and crossfades in from the last good frame over 8 frames, then fades in over 16 frames. A longer gap is a dropout: silence, counted once (Receiver::conceal). Partly late packets count as late (0.4).

5. Plugins

All units are AU aufx / <subtype> / Allc, version 65536. In act they are registered in-process with AUAudioUnit.registerSubclass(VBAudioUnit.self, …) and made directly (App/VoiceUnits.swift), with no extension lookup (0.7.2). The extensions stay in the bundle for other hosts. process() is allocation-free (VocalBundle rule). Parameters come from Docs/PLUGIN_SPECS.md, which build/vbparams writes.

11. Known issues and untested

  • Untested on hardware:

- the Mac's real input device as Tx, and Rx → Mac outputs (tests use a test signal and -actRxEcho); - Rx → vocal input, and Rx → iPad output.

  • Third-party interop is untested: AES67 streams through SAP, Dante, an external grandmaster, hardware timestamps, DSCP on the wire, an IGMP-snooping switch.
  • Bonjour for act Receiver is untested, because Local Network permission is not granted on the test Mac. Tests dial fixed ports.
  • Migration of 0.8 saved patches on a real iPad: untested.
  • The Mac's system audio as a source: not built.
  • Vocal in → out with the full voice chain: untested (22.8 ms is the units' reported sum). CPU of level, ess, smooth and tone: untested. pitch2's CPU on an older iPad: untested (about 8× pitch).
  • Background behaviour on a real iPad (lock, a real call, Siri): untested, because the simulator does not suspend apps.
  • Trackpad or mouse scroll over act on an iPad is on the device checklist. A UIKit scroll assertion crashed the Designed-for-iPad build on the Mac (0.4 soak).
  • Three-node run history: run 1 had a ~320 ms send stall on the simulator node; in run 2 every node lost PTP announces on en1 for ~140 s, giving a split clock. Run 3 and the 0.8.1 run passed.
